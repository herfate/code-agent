# 功能测试用例设计 — test_case_design.json

## JSON 顶层结构

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `version` | string | 是 | 固定 `"1.0"` |
| `meta` | object | 是 | 设计元信息与统计 |
| `columns` | array | 是 | Excel 列定义（顺序即导出列序） |
| `cases` | array | 是 | 测试用例行，每项对应 Excel 一行 |
| `open_questions` | object | 是 | 待澄清问题 |

---

## meta 字段

```json
{
  "requirement_source": "{{requirement_source}}",
  "design_time": "{{design_time}}",
  "material_type": "requirement_with_code",
  "summary_zh": "",
  "total_count": 0,
  "positive_count": 0,
  "negative_count": 0,
  "boundary_count": 0,
  "ready_for_review": false,
  "blocking_questions_count": 0,
  "non_blocking_questions_count": 0
}
```

| 字段 | 说明 |
|------|------|
| `material_type` | `requirement_doc`（纯需求）或 `requirement_with_code`（有需求且附代码参考）；仅记录资料形态，不影响用例设计策略 |
| `ready_for_review` | 无阻塞级问题时为 `true`；`blocking_questions_count > 0` 时必须为 `false` |
| `*_count` | 必须与 `cases` 数组实际统计一致 |

---

## columns 定义（Excel 表头，顺序固定）

```json
[
  { "key": "module", "header": "功能模块", "width": 15 },
  { "key": "sub_module", "header": "子模块", "width": 15 },
  { "key": "feature", "header": "功能点", "width": 20 },
  { "key": "test_scenario", "header": "测试场景", "width": 40 },
  { "key": "case_type_label", "header": "正反例", "width": 10 },
  { "key": "steps_text", "header": "操作步骤", "width": 50 },
  { "key": "expected_results_text", "header": "预期结果", "width": 50 },
  { "key": "data_sql_text", "header": "数据表", "width": 40 },
  { "key": "review_status", "header": "评审加用例", "width": 12 }
]
```

> 导出 Excel 时：`columns[].key` 对应 `cases[]` 同名字段；`*_text` 字段为已格式化的单元格文本。

---

## cases 每项字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `case_id` | string | 是 | 用例编号，如 `TC-001` |
| `module` | string | 是 | 功能模块 |
| `sub_module` | string | 是 | 子模块 |
| `feature` | string | 是 | 功能点 |
| `test_scenario` | string | 是 | 测试场景（叶子节点，可直接执行） |
| `case_type` | string | 是 | `positive` / `negative` / `boundary` |
| `case_type_label` | string | 是 | 中文：`正例` / `反例` / `边界` |
| `steps` | string[] | 是 | 操作步骤列表（有序） |
| `steps_text` | string | 是 | 步骤合并文本：`1-xxx\n2-yyy` |
| `expected_results` | string[] | 是 | 预期结果列表（有序） |
| `expected_results_text` | string | 是 | 预期结果合并文本：`1-xxx\n2-yyy` |
| `data_sql` | string[] | 是 | SQL 校验语句列表；无则 `[]`，对应 `data_sql_text` 为 `""` |
| `data_sql_text` | string | 是 | SQL 合并文本，多条用 `\n` 分隔 |
| `review_status` | string | 是 | 默认 `未评审` |
| `linked_req` | string | 否 | 关联需求条目 ID |

---

【强制 — 机读门禁】
1. cwd 根目录必须存在 `test_case_design.json`，且可被 `JSON.parse` 解析。
2. 必填顶层字段：`version`、`meta`、`columns`、`cases`、`open_questions`。
3. `meta.total_count === cases.length`；`positive_count` / `negative_count` / `boundary_count` 与 `cases[].case_type` 统计一致。
4. `blocking_questions_count > 0` 时 `meta.ready_for_review` 必须为 `false`。

6. `columns` 顺序与上表一致，共 9 列；`cases` 每项须包含 `columns[].key` 对应的全部字段。
7. 禁止输出 Markdown 表格替代 JSON；禁止在 JSON 文件外包裹 ```json 代码块。
